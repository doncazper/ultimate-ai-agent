# v0.104.0 Release Notes

Status: current release notes.

v0.104.0 is the Founder Command Center functioning-units and truth-binding
hardening baseline. It keeps the repository contract-first, local-first,
review-gated, disabled by default, and non-production by default while making
Action Inbox, Memory context-pack proposals, Today/Actions/Evidence visibility,
Local Models status, connector-readiness posture, and Control Center shell
language more backend-owned and verifier-backed.

## Scope

- Promote the active product/package baseline to `v0.104.0` / `0.104.0`.
- Preserve `checkpoint-m169` as the latest accepted repository checkpoint and
  `checkpoint-m166` / `checkpoint-m167` as the latest accepted local model lane
  checkpoints.
- Harden `/actions` and Founder Loop shell truth so mock/degraded fallback data
  cannot claim backend-owned authority truth or commit readiness.
- Add operational maturity verifier probes for read-only Local Models status,
  source readiness, Action Inbox approval envelope and receipt visibility, and
  Evidence Timeline no-authority flags.
- Record Memory context-pack proposal readiness in the operational maturity
  manifest with backend route, test, and verifier refs.
- Keep Local Models CLI parity path-backed through `scripts/dev/uaa_local_model.py`.
- Add portfolio current-state, case-study, and tag-catalog docs that preserve
  blocked, partial, mock-only, proposal-only, and status-only language.

## Non-Goals

v0.104.0 does not add production authority, public distribution, public beta,
signed installer readiness, hosted deployment, runtime model/provider calls,
unrestricted web fetching, browser automation, shell/subprocess authority,
connector writes, live email/calendar runtime, account auth, plugin runtime
import, arbitrary plugin execution, mobile control, memory writes, context
injection, generic action execution, raw prompt export, raw provider payload
export, credential handling, or raw private-content persistence.

## Verification Notes

This baseline should be verified with the current baseline checker,
documentation integrity verifier, operational maturity verifier, OpenAPI
contract verifier, focused backend route/storage tests, and Control Center
frontend checks before tagging.
