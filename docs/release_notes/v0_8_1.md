# Release Notes v0.8.1

v0.8.1 implements Milestone M4.5 (Truth Source Router + Evidence Governance foundation).

## M4.5 Truth Source Governance

- Added truth source manifests with explicit source type, authority level, consent requirements, data classification, freshness references, and provenance refs.
- Added deterministic grounding policies for creative, factual, project truth, live, weather, legal, medical, financial, security, metrics, news, and code status tasks.
- Added source selectability checks so consent-gated and credential-secret sources are not selected.
- Enforced that model output is not authority and memory cannot be authoritative.

## Evidence Governance

- Added claim evidence, evidence items, evidence manifests, unsupported-claim labeling, redaction metadata, retrieval logs, and freshness policies.
- Added deterministic conflict reports and source conflict resolution rules for canonical-vs-memory and structured-source-vs-document cases.
- Added freshness classification and enforcement for supplied evidence timestamps.

## Truth Router + API Boundary

Added non-executing validation/preview endpoints:

```text
POST /truth/sources/validate
POST /truth/grounding-policy/validate
POST /truth/evidence/validate
POST /truth/route
POST /truth/freshness/check
POST /truth/conflicts/validate
```

The router accepts only caller-supplied source manifests and returns source IDs, reason codes, safe unsupported-claim decisions, and human-review requirements.

## Explicitly Not Implemented

No M5 Minimum Lovable Kernel, scanners, companion proactivity, Skill Factory, self-improving code, autopilot workflows, real provider integrations, web fetching, real model calls, embeddings, pgvector, production memory database, external tools, browser automation, high-autonomy execution, or production truth connectors were added.
