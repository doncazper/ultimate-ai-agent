# Release Notes v0.14.0

## M10 Manual Local Loopback Smoke Transport + Runtime Readiness Harness

v0.14.0 is the first carefully constrained local loopback smoke milestone after the accepted v0.13.2 baseline.

Added:

- manual smoke policy, request, result, validation, and fake transport contracts
- isolated `StdlibLoopbackSmokeTransport` for manual local loopback HTTP smoke checks
- `scripts/local_loopback_smoke.py`, disabled by default and requiring explicit manual flags
- validation-only API route: `POST /model-runtime/local/smoke/validate`
- Foundation Gate M10 checks for isolated stdlib network use, fixed prompt enforcement, approval requirement, fake-transport gate usage, and absence of public smoke execution routes
- verifier allowance for stdlib `urllib` only in the isolated manual smoke transport

Guardrails preserved:

- no cloud model calls
- no provider SDKs
- no API keys or secret reads
- no tokenizers or billing APIs
- no user prompts, memory, files, context packs, secrets, or task content in smoke payloads
- no real network/model calls in tests, CI, `verify_all.py`, or Foundation Gate
- no public API route that performs real local loopback execution
- no production auth, OAuth, persistence, scanners, browser automation, SDK/A2A runtime delegation, or external actions

Manual smoke output remains non-authoritative. It is a readiness signal only, not evidence of truth.
