# Release Notes v0.18.0

Status: Current release notes for M14 Web Control Center Local Backend Connection Stabilization.

v0.18.0 implements M14 inside the existing Web Control Center shell. It improves how the shell connects to local backend APIs and how it reports live, degraded, offline-safe, and mock fallback states.

Changed:

- active version metadata now points to `0.18.0`.
- README, documentation index, canonical map, import docs, master plan, and Foundation Gate plan point to v0.18.0.
- `apps/control-center/src/api/baseUrl.ts` validates API base URLs before client requests.
- Vite dev server proxy maps relative `/control-center/*` and `/runtime/*` requests to `http://127.0.0.1:8000` only.
- relative API paths, `localhost`, `127.0.0.1`, and loopback IPv6 are supported.
- external absolute API URLs are blocked.
- secret-like API base URL strings are rejected without displaying secret-like values.
- frontend data loading distinguishes fully live, degraded partial-live, and mock fallback states.
- mock fallback remains visibly mock and non-authoritative.
- M14 frontend tests, static verifier checks, and Foundation Gate criteria cover the local backend connection policy.
- `docs/control_center/LOCAL_BACKEND_CONNECTION.md` documents the local-only connection boundary.

Unchanged:

- backend OpenAPI path count remains `74`.
- Control Center backend routes remain read-only/preview-only.
- the frontend still declares exactly one POST target: `/control-center/actions/preview`.
- Python Agent Core remains the brain.
- local browser smoke remains manual, local-only, unauthenticated-profile-free, and non-authoritative.
- M15 Approval Queue + Receipt/Event Viewer UI remains future work.

Not added:

- backend API route.
- approval queue UI.
- receipt/event viewer UI.
- production Control Center authority.
- public execution API.
- runtime/model/provider calls.
- remote dispatch.
- mobile/native app or sensor access.
- plugin enablement.
- Chrome authenticated profile control.
- Computer Use automation.
- iOS/macOS build workflow.
- auth, credentials, cookies, Authorization headers, or API keys.
- analytics/auth/payment/SaaS SDKs.
- external API host support.
- production persistence.
- dependency.
- external action.
