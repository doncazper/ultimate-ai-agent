# Release Notes v0.13.2

## M9.5 Loopback Runtime Hardening and Approval API Cleanup

v0.13.2 is a targeted patch release after the accepted v0.13.1 baseline.

Fixed:

- `deny_non_loopback=false` is rejected by `LoopbackRuntimePolicy` and can no longer be accepted as a weakening policy.
- non-loopback `allowed_hosts` entries are rejected at policy validation time.
- private LAN and public IP endpoints remain denied by adapter validation.
- adapter-level `NON_LOOPBACK_HOST_DENIED` remains as defense in depth.
- `/approvals/validate` now loads supplied grants through a public `LocalApprovalAuthority.load_grant_for_validation` helper instead of mutating private authority state.
- Foundation Gate includes M9.5 checks for hostile policy models, public/private IP endpoint denial, and approval API helper usage.

Guardrails preserved:

- no cloud model calls
- no provider SDKs
- no API keys or secret reads
- no tokenizers or billing APIs
- no real network/model calls in tests, CI, `verify_all.py`, or Foundation Gate
- no production auth, OAuth, persistence, scanners, browser automation, SDK/A2A runtime delegation, or external actions

The model remains non-authoritative. Local loopback responses and simulated fallback responses are marked as not truth authority.
