# Mobile Companion Backlog

Status: Future planning only, v0.14.4

The Mobile Companion backlog starts after runtime readiness, API/control-center contract stabilization, and web Control Center foundation. It does not implement a mobile app in v0.14.4.

## Mobile Phase A - Planning/Contracts

- mobile companion canonical docs.
- device capability broker canonical docs.
- OpenAPI contract requirements.
- future permission manifest schema planning.
- no app.

## Mobile Phase B - Control Center Readiness

- approval queue API.
- receipts API.
- event viewer API.
- runtime status API.
- notification policy contracts.

## Mobile Phase C - Web Control Center First

- browser UI shell.
- approval action center.
- event/receipt viewer.
- safe local-dev runtime status.
- no mobile sensors yet.

## Mobile Phase D - Mobile Companion Shell

- mobile login/pairing placeholder.
- approval notifications.
- receipt viewer.
- safe status dashboard.
- kill switch.
- no camera, microphone, or GPS yet.

## Mobile Phase E - Mobile Capture Inbox

- share sheet.
- selected file/photo import.
- typed notes.
- user-reviewed memory/file write.

## Mobile Phase F - Camera/OCR

- document scan.
- QR scan.
- OCR/evidence refs.
- no automatic memory write.

## Mobile Phase G - Location

- one-time location.
- navigation session.
- approximate/precise distinction.
- no background location by default.

## Mobile Phase H - Microphone/Voice

- push-to-talk only.
- short clips.
- transcript review.
- no passive always-listening.

## Mobile Phase I - Advanced Device Capabilities

- NFC/Bluetooth/motion.
- contacts/calendar scoped access.
- biometrics/passkeys.
- emergency stop / kill switch hardening.

## Explicit Non-Goals

- no background surveillance.
- no passive always-listening.
- no silent photo/contact/calendar scans.
- no unapproved sends.
- no hidden sensor access.
- no mobile autonomous actions.
- no mobile agent brain.
